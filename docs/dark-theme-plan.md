# 深色模式配色修改计划

日期：2026-10-04。配色已确认，计划已执行；实际验证结果见 [验收记录](validation.md)。以下保留已批准的修改范围、步骤与验收要求。

目标：采用「中性石墨灰 + 柔和蓝」。背景和面板使用中性灰，蓝色集中用于主要操作、选中提示和键盘焦点；收藏、警告、成功与错误保持独立状态色。

**1. 修改范围与现状**

- 预期代码改动集中在 `src/styles.css`，复用现有 CSS 变量和主题覆盖机制。
- 默认 `:root` 定义深色主题，`:root[data-theme='light']` 覆盖浅色主题。`src/App.tsx` 已处理深色、浅色和跟随系统切换，无需修改主题逻辑、设置接口或持久化结构。
- 本次只调整颜色及与配色直接相关的焦点阴影。沿用现有字体、尺寸、间距、对齐、圆角、布局、滚动条形态和交互行为。
- 浅色主题保持现有效果。新增公共颜色变量时，为浅色主题显式保留原值；组件颜色规则的变化限定在深色主题。

**2. 已确认的变量映射**

| CSS 变量 | 深色目标值 | 用途 |
| --- | --- | --- |
| `--bg` | `#161719` | 主窗口、列表底色、输入框底色 |
| `--panel` | `#1C1D20` | 侧栏、搜索框、弹窗底部 |
| `--raised` | `#242529` | 弹窗、菜单、次要按钮、项目图标底色 |
| `--hover` | `#2B2D31` | 悬停背景 |
| `--selected` | `#273247` | 当前项目、当前分类背景 |
| `--border` | `#32343A` | 边框、分隔线、滚动条默认滑块 |
| `--text` | `#E6E7EB` | 标题、项目名称、主要内容 |
| `--secondary` | `#ADB0B8` | 说明、分类、普通操作图标 |
| `--muted` | `#8C9099` | 路径、时间、快捷提示、占位文字 |
| `--accent` | `#96B2F5` | 强调图标、选中标记 |

`--shadow` 沿用现有值 `0 12px 40px #0005`，用于菜单、弹窗和提示浮层。

**3. 按顺序实施**

1. 替换默认深色主题变量，并加入 `--success`、`--backdrop`。浅色主题分别使用原成功色 `#73AA8A` 和原遮罩色 `#080D1880`。
2. 将 `.clean-dot`、`.status-dot`、`.toast > svg` 中写死的成功色统一替换为 `var(--success)`；保留忙碌状态使用 `--star`、错误提示使用 `--danger` 的覆盖顺序。将 `.dialog::backdrop` 改用 `var(--backdrop)`。
3. 在深色主题中，将未选中项目行的悬停底色改为 `--hover`；选中行仍使用 `--selected`，保留左侧蓝色标记和淡蓝边框，项目名称保持 `--text`。确认选中行悬停时不会被普通悬停底色覆盖。
4. 在深色主题中，将 `.category-tag` 和 `.row-open` 的默认前景色改为 `--secondary`，选中项目的打开按钮和悬停、键盘聚焦中的打开按钮使用 `--accent`。保留已有品牌标志、选中项目图标和主要按钮的蓝色，普通工具图标继续使用灰色。
5. 保留已有键盘焦点描边与搜索框蓝色焦点边框，去掉深色搜索框额外的外部蓝色阴影。继续沿用滚动条的宽度、透明轨道、圆角，以及默认、hover、active 的变量映射。
6. 检查辅助文字在选中底色上的可读性。若选中行的路径或小标签对比不足，仅在该状态改用现有 `--secondary`，保持已确认的基础色值。

深色专用规则需同时覆盖显式深色、跟随系统解析为深色，以及尚未设置 `data-theme` 时的默认深色。可使用 `:root:not([data-theme='light'])` 限定，并注意规则顺序与优先级。

**4. 验证与验收**

- 静态检查：核对所有目标色值、三处成功色引用、弹窗遮罩引用及浅色覆盖；检查 diff，确认修改范围符合本计划。
- 构建检查：执行已有 `npm run build`，完成配套扩展构建、TypeScript 检查和 Vite 生产构建。本次纯样式改动不新增测试框架或仅断言色值的测试。
- 真实界面：使用 `npm run desktop` 启动 Tauri/WebView2，以工作区内 `.validation/` 下的隔离数据目录设置 `REPOJUMP_TEST_DATA`，在其中准备有项目、收藏、分类及较长路径的场景。
- 主界面：检查搜索框、侧栏、列表、选中详情和状态栏，以及普通、悬停、选中、选中后悬停、键盘焦点、禁用状态。蓝色用于主要操作和选中提示，主要文字与辅助信息层次清楚。
- 浮层与提示：检查项目菜单、设置弹窗、分类弹窗、VS Code 启动内容弹窗、确认弹窗、成功/错误提示、警告和空状态。无法实际触发的场景可用独立页面夹具验证样式，并明确标记模拟验证。
- 尺寸与滚动：检查默认 1080×740 和最小 680×480 窗口、长项目名和长路径、列表与弹窗滚动；布局、截断和底部操作区保持可用。
- 主题回归：通过设置切换深色、浅色、跟随系统，检查即时更新及重启后恢复；跟随系统的深浅切换须实际观察，模拟结果单独记录。
- 对比检查：计算主要文字、辅助文字、按钮文字与实际背景的对比，正文目标至少 4.5:1；检查焦点和选中标记可辨认。必要时优先调整组件使用的现有颜色变量。
- 保存主界面、菜单、设置弹窗的深色截图与浅色对照截图到 `.validation/`，逐张检查。实际完成的验证再简要记录到 `docs/validation.md`，不提前填写通过结论。

完成标准：已确认的深色配色应用到完整界面，各交互状态清楚，浅色效果及主题切换保持正常，构建通过，并有实际界面验证结果和明确的未验证项。
