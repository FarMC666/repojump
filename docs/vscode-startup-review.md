# VS Code 启动内容与 0.1.4 集成审查

审查基准为撤销第一次集成后的本地 `main`，其文件内容与 `c2f8885` 一致。功能实现基于该 0.1.4 基准重新集成，保留 `profileId`、`dataLocation`、StorageManager、托盘语言同步以及 `.repojump` 扫描排除规则。

## 发现与修正

第一次集成对 `vscodeStartupOverrides` 做了严格相等判断。0.1.4 配置没有该字段；两份原本可由重复迁移修复恢复的配置，只要一份新增启动选项，就会被判为不同配置，回退到 AppData。新回归测试在第一次集成代码上复现 `storageLocationFallback`，修正后通过。

现在仍按 0.1.4 原规则检查根目录路径、手动项目、收藏、Recent、分类和设置。启动选项只检查共同项目是否存在冲突；没有冲突时合并新增选项，采用已有根目录配置的 profile 和 Root 标识，并对齐恢复副本。同一项目配置不同选项、其他用户记录不同、或自定义位置属于另一 profile 时，原保护继续生效。

首版功能分支基于 0.1.1，该版本不识别 `profileId` 和 `dataLocation`，保存时会丢失这些未知字段。因此使用旧版功能程序读取新版真实配置存在兼容风险。候选发布程序保留 0.1.4 数据模型；新增持久化测试验证保存启动内容时这些字段与原有用户记录不变。

历史验收记录显示不同启动环境曾生成不同 AppData 配置。此次只读采样结果一致，但直接从工具环境启动发布程序仍复现原子保存的跨盘错误 `os error 17`；实际目录仍是根目录，没有覆盖根目录原数据。单独创建 `Shell.Application` 并调用 ShellExecute 也不足以取得正常桌面启动环境。

改用资源管理器窗口的 `Document.Application` 代理启动后，发布程序正常保存。真实 Settings 显示 `D:\code\.repojump`；保存相同设置并再次以该方式启动，没有存储告警。新增空启动覆盖字段之外，原配置逐字段相等，包括 profile、Root 标识、全部 Recent、收藏、分类和设置。这与微软说明的[从 Explorer 文件夹视图取得 Shell 自动化对象](https://devblogs.microsoft.com/oldnewthing/20131118-00/?p=2643)方式一致。

## 代码边界

| 范围 | 集成处理 |
| --- | --- |
| 用户状态与保存 | 启动覆盖为新增用户元数据；使用 0.1.4 的原子保存、profile 冲突及只读保护。恢复默认仅删除该项目的覆盖。 |
| 配置迁移 | 保留 0.1.4 存储管理；原记录保持相等约束，新选项仅在无冲突时合并。 |
| 启动请求 | 从 StorageManager 获取已解析的 AppData bootstrap 路径。工作区与一次性请求不随偏好数据迁移。 |
| 文件启动 | 保存和启动均检查项目内现有文件；独立参数传递目录和文件，无 shell 拼接。 |
| Git Graph | 仅安装配套 VSIX；工作区限定目标项目，15 秒请求与回执等待、30 秒安装上限，一次性消费。 |
| 最近记录与提示 | 已打开窗口保留；启动内容失败及 Recent 保存失败同时提示，存在警告时快捷启动窗口保持可见。 |
| 0.1.4 原功能 | 托盘语言同步、设置的数据位置选择、发现规则和依赖锁文件与审查基准一致。 |

## 验证

- 34 项 Rust、5 项 Vitest、9 项配套扩展测试通过；TypeScript、fmt、Clippy warnings as errors 和生产前端构建通过。
- 回归覆盖旧配置缺少启动字段、两份配置新增不同项目选项、同一项目冲突、原字段保存、迁移与重启。
- 使用真实用户配置的只读副本，在隔离目录重现历史重复 profile 与 Root 标识，加入启动内容后恢复根目录，没有存储警告；已有用户记录保留。
- 真实 Tauri / VS Code 验收通过文件聚焦、Git Graph 目标窗口、自定义及自动位置迁移、固定 AppData 工作区位置和重启恢复。
- 发布程序和普通桌面数据位置的最终结果记录于 [验收记录](validation.md)。

在此开发宿主运行发布程序时，应通过真实 Explorer 文件夹视图启动。验收脚本 `.validation/start-reviewed-release.ps1` 使用该方式；不能用普通工具子进程启动的保存失败判断产品代码是否回退。

脚本、真实配置副本及诊断结果位于忽略的 `.validation/`，不纳入 Git。
